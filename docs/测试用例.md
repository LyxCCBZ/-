## 3. 关键手工/集成测试用例

### TC-01 注册与登录

- 前置条件：MongoDB 可用，users 集合无同名用户。
- 步骤：
  1. 打开 /register。
  2. 输入用户名 test_user、密码 test123456、确认密码 test123456。
  3. 提交后打开 /login。
  4. 输入相同账号密码登录。
- 输入：test_user / test123456。
- 预期输出：注册提示成功；登录后进入“我的问卷”页面。
- 实际结果：通过。用户名写入 users，密码字段为哈希；错误密码被拒绝。

### TC-02 创建问卷

- 前置条件：已登录。
- 步骤：打开 /surveys/new，填写标题“测试问卷”，说明“自动化测试”，勾选匿名和重复填写，提交。
- 输入：title=测试问卷；description=自动化测试；allow_anonymous=on；allow_multiple=on。
- 预期输出：创建 draft 问卷，跳转管理页；surveys 文档含随机 public_id、owner_id、状态 draft。
- 实际结果：通过。管理页显示 0 道题，公开链接尚未展示。

### TC-03 用户数据隔离

- 前置条件：用户 alice 创建了问卷 S；用户 bob 已登录。
- 步骤：bob 直接访问 /surveys/S。
- 输入：问卷 S 的 ObjectId。
- 预期输出：返回 404，bob 不能看到该问卷。
- 实际结果：通过，owner_id 校验生效。

### TC-04 添加单选题与数字题

- 前置条件：问卷为 draft。
- 步骤：
  1. 添加单选题，选项为“计算机、软件工程、其他”，必答。
  2. 添加数字题，最小值 0，最大值 120，只允许整数。
  3. 查看 MongoDB questions 集合。
- 输入：题库字段见步骤。
- 预期输出：两道题的 order 为 1、2；选项自动获得 A/B/C；数字题 validation.integer_only=true。
- 实际结果：通过。

### TC-05 题目配置错误校验

- 前置条件：问卷为 draft。
- 步骤：添加单选题，但选项只写一行“唯一选项”。
- 输入：type=single；options=唯一选项。
- 预期输出：题目不写入；页面提示“选择题至少需要两个选项”。
- 实际结果：通过，questions 数量不增加。

### TC-06 多选数量校验

- 前置条件：多选题设置 min_select=2、max_select=3，选项 A/B/C/D。
- 步骤：
  1. 只提交 A。
  2. 提交 A、C。
- 输入：answer=[A]；answer=[A,C]。
- 预期输出：第一组返回 422，提示至少选择 2 项；第二组进入下一题并保存 ["A","C"]。
- 实际结果：通过。

### TC-07 文本长度校验

- 前置条件：文本题设置 min_length=3、max_length=5，必答。
- 步骤：
  1. 提交“你好”。
  2. 提交“你好呀”。
- 输入：answer=你好；answer=你好呀。
- 预期输出：第一次返回 422，提示至少 3 字；第二次通过。
- 实际结果：通过，错误页保留原输入。

### TC-08 数字范围与整数校验

- 前置条件：数字题设置 0-120、只允许整数。
- 步骤：
  1. 提交 121。
  2. 提交 18.5。
  3. 提交 18。
- 输入：answer=121；answer=18.5；answer=18。
- 预期输出：前两组失败并提示范围/整数错误；18 通过并保存为 int。
- 实际结果：通过。

### TC-09 单向跳转规则校验

- 前置条件：问卷 draft 中有 Q1、Q2、Q3。
- 步骤：
  1. 为 Q1 添加规则：选 A 跳到 Q3。
  2. 为 Q1 添加规则：选 B 结束问卷。
  3. 尝试把 Q1 的规则目标设为 Q1 自己或 END 之外的更早题。
- 输入：operator=eq；value=A；target=Q3。operator=eq；value=B；target=END。
- 预期输出：前两条保存成功；目标不是后续题时拒绝并提示。
- 实际结果：通过。跳转目标校验保证只能向前。

### TC-10 填写时执行跳转

- 前置条件：Q1 选 A 跳到 Q3；Q2 为应被跳过的文本题；Q3 为年龄数字题；问卷已发布。
- 步骤：
  1. 开始答卷并选择匿名。
  2. Q1 提交 A。
  3. 观察下一页。
- 输入：Q1 answer=A。
- 预期输出：直接显示 Q3，不显示 Q2；response.answers 中只有 Q1、Q3。
- 实际结果：通过，页面和数据库均验证。

### TC-11 提交与统计

- 前置条件：完成 TC-10，Q3 输入 25 并提交。
- 步骤：
  1. 打开 /surveys/ID/stats。
  2. 查看总提交数、Q1 选项计数、数字题平均值。
  3. 打开 JSON API。
- 输入：Q3 answer=25。
- 预期输出：response.status=submitted；统计 response_count 增加；Q1 的 A 计数增加；数字平均值 25.0；被跳过的 Q2 回答人数为 0。
- 实际结果：通过。

### TC-12 禁止重复提交

- 前置条件：问卷 allow_multiple=false；同一账号已提交一份答卷。
- 步骤：再次打开公开链接并开始填写。
- 输入：anonymous=on。
- 预期输出：拒绝开始，提示“不允许重复提交”。
- 实际结果：通过。respondent_key 即使匿名也可用于去重。

### TC-13 关闭问卷

- 前置条件：问卷已发布。
- 步骤：创建者点击关闭；填写者再次尝试开始。
- 输入：无。
- 预期输出：surveys.status=closed；新的 start 请求被拒绝；已提交数据仍可统计。
- 实际结果：通过。

### TC-14 发布后锁定题目结构

- 前置条件：问卷已发布。
- 步骤：尝试向已发布问卷添加题目。
- 输入：新题目字段。
- 预期输出：提示“问卷发布后不能修改题目”；questions 数量保持不变。
- 实际结果：通过。

### TC-15 双会话重复提交防护

- 前置条件：问卷 `allow_multiple=false`；同一账号在两个独立会话中登录。
- 步骤：第一个会话开始填写；第二个会话再次开始同一问卷。
- 预期输出：第一个会话再次开始时会回到原答卷；第二个会话提示存在未完成答卷，不创建新文档。
- 实际结果：通过。同一账号最终只能提交一份正式答卷。

### TC-16 非有限数字校验

- 前置条件：数字题允许普通数值输入。
- 步骤：分别提交 `nan`、`inf`、`-inf`、`Infinity` 和 `1e309`；同时用这些值配置数字范围和跳转条件。
- 预期输出：全部被拒绝，不允许写入非有限数字。
- 实际结果：通过。

### TC-17 登录跳转安全

- 前置条件：用户已注册。
- 步骤：分别提交外部 URL、协议相对 URL 和含反斜杠的 `next` 参数。
- 预期输出：登录成功后统一跳转 `/dashboard`，不接受站外地址。
- 实际结果：通过。

### TC-18 问卷状态边界

- 前置条件：分别准备草稿问卷、已发布问卷和过期问卷。
- 步骤：关闭草稿；将已发布问卷的截止时间改为过去时间；填写过程中关闭问卷。
- 预期输出：草稿不能被关闭；过期问卷自动关闭并更新时间；关闭后不接受新的答案。
- 实际结果：通过。

### TC-19 匿名开关与身份隔离

- 前置条件：问卷关闭匿名选项。
- 步骤：填写者仍提交 `anonymous=on`。
- 预期输出：系统忽略该参数，按非匿名答卷保存 `respondent_id`。
- 实际结果：通过。

### TC-20 用户信息暴露检查

- 前置条件：匿名与实名答卷各一份，由两个不同账号产生。
- 步骤：检查填写页、完成页、数据库、统计页面和统计 JSON API；再用他人账号访问答卷、管理页和统计接口。
- 预期输出：页面和 API 不出现 `respondent_id`、`respondent_key`、访问令牌哈希或用户名；他人访问返回 404。
- 实际结果：通过，专项隐私检查 39 项全部通过。

## 5. 测试结论

- 核心需求均有自动化或集成用例覆盖。
- 条件跳转在页面和数据库层同时验证，确认被跳过题目不会产生 answer。
- 校验失败不会写入答案。
- 统计只计算已提交答卷。
- 账号隔离、重复提交限制、关闭问卷和发布锁定均符合预期。
- 安全与隐私边界已覆盖，包含匿名身份、令牌、统计接口和跨账号访问。
- 共 22 项自动化测试全部通过。
