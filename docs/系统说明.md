# 系统说明

## 1. 项目定位

本系统是课程大作业第一、第二阶段持续演进的在线问卷平台。第一阶段完成了“问卷创建—题目配置—链接分发—登录填写—条件跳转—提交保存—统计查看”的闭环；第二阶段在不推倒原有功能的前提下，新增题库、题目共享、不可变版本、历史恢复和跨问卷统计，重点展示 MongoDB 文档建模、快照隔离与版本化数据设计。

## 2. 用户角色

| 角色 | 能力 |
| --- | --- |
| 未登录访客 | 注册、登录；不能创建或填写问卷 |
| 登录用户 | 创建问卷、管理自己的问卷、发布或关闭问卷、查看自己的统计结果 |
| 问卷创建者 | 查看自己问卷的题目、公开链接、提交情况、整卷或单题统计 |
| 问卷填写者 | 通过公开链接进入，登录后逐题填写；可匿名提交或被记录账号 |
| 题库所有者 | 创建题库题目、创建新版本、恢复旧版本、共享题目、查看全部使用情况和跨问卷统计 |
| 被共享用户 | 在共享范围内查看题目、在自己的草稿问卷中选用、查看自己问卷范围内的使用与统计；不能修改所有者题库，可复制为自有题目 |

权限边界：问卷管理接口都会校验 owner_id；其他账号直接访问管理页会返回 404，避免泄露问卷是否存在。

## 3. 功能模块

### 3.1 账号模块

- 注册：用户名为 3-30 位中文、字母、数字或下划线，用户名统一小写后保证唯一。
- 密码：至少 6 位，使用 Werkzeug 默认 scrypt 哈希保存，不保存明文。
- 会话：登录后 Flask 签名 Cookie 保存用户 ID，退出时清空会话。
- 登录保护：问卷管理、公开链接进入、答题操作均要求登录。

### 3.2 问卷管理模块

- 新建草稿：填写标题、说明、是否允许匿名、是否允许重复填写。
- 设置：修改标题、说明、截止时间；草稿阶段还可修改匿名和重复填写开关。
- 发布：至少有一道题且截止时间有效时才能发布；发布后生成公开链接。
- 关闭：创建者可主动关闭问卷；达到截止时间后系统自动关闭。
- 公开链接：/survey/公开编号，编号由 secrets 随机生成并建立唯一索引。

### 3.3 题目模块

支持四种输入控件，覆盖需求中的三类题型：

| 题型 | 用途 | 配置 |
| --- | --- | --- |
| single | 单选题 | 至少两个选项、是否必答 |
| multiple | 多选题 | 选项、最少选择数、最多选择数、是否必答 |
| text | 文本填空 | 最少字数、最多字数、是否必答 |
| number | 数字填空 | 最小值、最大值、是否只允许整数、是否必答 |

选项编号由系统自动生成 A、B、C……，跳转规则通过编号引用选项，避免用户修改选项文字后规则失效。

问卷发布后题目结构锁定，防止已有答卷与题目结构冲突；草稿阶段支持添加、删除题目，删除题目时会自动清理指向该题目的跳转规则。

### 3.4 跳转模块

每道题可以有多条跳转规则，规则包含“条件”和“目标题目”。目标可以是后续任意题目，也可以是“结束问卷”。规则按数组顺序匹配，命中第一条即生效；未命中时默认进入下一题。

支持的条件：

| 题型 | 条件 |
| --- | --- |
| 单选 | 等于、不等于某个选项 |
| 多选 | 包含任意、包含全部、不包含某些选项 |
| 数字 | 等于、不等于、大于、大于等于、小于、小于等于、介于区间 |
| 文本 | 包含、等于、不等于 |

只允许跳向后续题目，从结构上避免死循环；需要提前结束时选择“结束问卷”。

### 3.5 填写模块

- 填写者登录后打开公开链接，阅读说明并开始答卷。
- 系统为每次答卷生成独立 response 文档和随机访问令牌。
- 每道题单独显示，提交后由服务端校验并计算下一题。
- 每次有效作答立即写入 MongoDB，刷新或中途退出不会丢失前面的答案。
- 全部完成或命中 END 规则后，答卷状态变为 submitted，并记录提交时间。
- 同一账号的多次填写通过 respondent_key 区分；当 allow_multiple=false 时禁止第二次提交。

### 3.6 统计模块

创建者可以查看：

- 问卷总提交数。
- 每道题的回答人数。
- 单选每个选项被选择的人数和百分比。
- 多选每个选项被选择的次数和百分比。
- 文本题全部回答内容。
- 数字题全部值、平均值、最小值、最大值。
- 通过“全部题目”和 Q1/Q2… 链接在整卷与单题视图之间切换。
- 通过 /api/surveys/问卷ID/stats 获取 JSON 统计结果。

统计只计算 status=submitted 的答卷；填写中的草稿不进入统计。

### 3.7 题库与版本模块

- 题库题目保存在 question_bank 集合中，代表题目的逻辑身份；题目内容保存在 question_versions 集合中，每个版本都是不可变快照。
- 新建题库题目自动创建 v1；修改题目不会覆盖旧版本，而是创建 v2、v3……并记录 parent_version_id。
- 恢复历史版本会以旧版本内容创建一个新版本，同时记录 restored_from_version_id，历史链不会丢失。
- 问卷从题库选题时，把指定版本的标题、题型、选项、校验配置复制到 questions 集合，并记录 library_question_id、library_version_id、library_version_number、library_owner_id。
- 问卷使用的是独立快照，因此题库后续创建新版本不会改变已有问卷；已发布问卷仍然锁定题目结构。
- 同一道题的不同版本可以同时被不同问卷使用；草稿问卷可以按需选择任意版本。
- 所有者可以按用户名共享题目；被共享用户可以直接在自己的问卷中使用，也可以复制为自有题目后独立改版。

### 3.8 跨问卷题目统计

- 按 library_question_id 找到所有问卷中的题目快照，再只统计这些问卷中 status=submitted 的答卷。
- 所有者查看该题在所有问卷中的使用与统计；被共享用户只看自己创建的问卷，避免通过共享题目窥探他人数据。
- 选择题按“选项 key + 该快照中的选项文本”合并统计，避免不同版本中同一编号含义变化导致误合并。
- 数字题合并计算平均值、最小值、最大值；文本题展示最多 200 条回答内容。
- 页面与 JSON API 均提供跨问卷统计结果。

## 4. 典型使用流程

1. 用户注册并登录。
2. 创建问卷草稿，设置匿名与重复填写策略。
3. 依次添加单选、多选、文本、数字题目。
4. 也可以先把常用题目保存到题库，再从题库选择指定版本加入问卷。
5. 为题目配置跳转规则，例如“第 1 题选 A 则跳到第 3 题”。
6. 设置截止时间并发布。
7. 将 /survey/公开编号 链接发给填写者。
8. 填写者登录后逐题作答，服务端校验并执行跳转。
9. 创建者在统计页查看实时汇总结果；在题库页查看同一道题跨问卷的汇总结果。

## 6. 第二阶段范围说明

第二阶段完整保留第一阶段的问卷创建、填写、跳转、校验、统计与隐私控制，同时完成需求变更中的八项要求：常用题目保存、题目共享、改题不影响旧问卷、历史版本与恢复、同一题目多版本并存、查看题目使用情况、题库管理、跨问卷统计。

核心策略是“逻辑题目 + 不可变版本 + 问卷快照”：question_bank 只保存当前版本指针与共享关系，question_versions 保存不可变内容，questions 保存问卷自己的使用快照。这样既支持题目复用，又保证已发布问卷和数据不会被后续改题破坏。

当前仍未实现题库题目的删除、回收站、批量导入导出和拖拽排序；这些不属于本次需求变更的硬性要求，可在后续迭代补充。
