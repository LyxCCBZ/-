### 3.1 开发阶段交互记录

> 本节按“用户下指令—AI 执行—用户追问—人工验收”的顺序记录开发过程。用户输入保留完整语义、功能预期和验收标准，AI 输出只摘录交付物与关键判断。P 编号与 3.2 节的任务级 Prompt 一一对应。

#### 3.1.1 需求拆解与第一阶段范围（P01）

**第 1 轮：用户下达任务**

> 老师给的文档是《大作业一第一阶段.docx》。先不要写代码，先把这个文档拆成可以执行的功能清单：要哪些页面、哪些数据对象、用户怎么操作、第一阶段做到什么程度。我的预期是能完整跑通“注册登录→创建问卷→添加题目→设置跳转→发布→登录填写→提交→查看统计”这一条链路，不是只做几个静态页面。技术栈按课程要求用 Flask + MongoDB，别引入现成问卷平台或低代码框架。

**AI 响应**

- 将课程要求整理为账号、问卷管理、题目、跳转、填写、统计、测试、文档八个模块。
- 给出页面清单、数据对象、问卷状态机和实施顺序。
- 指出课程中“三种题型”与“填空题包含文本、数字两种”存在表述差异，建议数据层使用 `single`、`multiple`、`text`、`number` 四种类型。

**第 2 轮：用户补充边界与功能预期**

> 我再确认几个边界：题目发布后如果还能改，之前填过的答卷就会和题目对不上，所以第一阶段发布后锁定题目和跳转结构，只能在草稿阶段增删题目。题目编辑、复制、拖拽排序、CSV 导出、生产部署都先不做。条件跳转要按回答内容走，不能写死在代码里。统计只看已提交的答卷，填到一半的草稿不算。你先按这个范围给出目录结构和实施顺序，确认后再开始写。

**AI 响应**

- 确认第一阶段边界，补充“发布后结构锁定”和“统计只读取 `submitted`”两条实现约束。
- 给出 `routes`、`services`、`templates`、`tests` 的目录规划，并说明先做数据层和业务服务，再接页面。

**人工验收**

范围与最终报告一致；四类题型、状态流转和阶段边界均按确认后的方案实现。

#### 3.1.2 MongoDB 模型与工程结构（P02—P03）

**第 1 轮：用户下达数据库设计任务**

> 数据库部分用 MongoDB，先把集合设计出来，不要把所有东西塞进一个集合。我要看到每个集合的字段、索引、JSON Schema，以及题目和答卷之间怎么关联。题型不同，校验字段也不同；跳转规则也要能按题目保存。哪些内容适合内嵌、哪些应该引用，你给出理由，别只给一个能跑的简化版。

**AI 响应**

- 设计 `users`、`surveys`、`questions`、`responses` 四个集合。
- 问卷通过 `owner_id` 引用用户，题目通过 `survey_id` 引用问卷，答卷答案内嵌在 response 中，跳转规则内嵌在题目中。
- 为用户名、公开编号、题目顺序和答卷状态分别设计唯一索引或组合索引。

**第 2 轮：用户追问匿名与并发限制**

> 匿名答卷不能保存用户 ID，但问卷又可能要求不能重复填写，这两件事怎么同时做到？不要在应用层随便查一下就算完成，两个人同时开答卷时也要拦住，最好让数据库兜底。JSON Schema 也要真正生效，格式不对的文档不能写进去。

**AI 响应**

- 匿名答卷不保存 `respondent_id`，改为保存不可逆的 HMAC `respondent_key`。
- 对禁止重复填写的问卷建立 `single_response=true` 的部分唯一索引，在数据库层阻止同一去重键生成第二份答卷。
- 四个集合启用 `$jsonSchema`，`validationAction=error`，并在应用层补充业务校验。

**第 3 轮：用户要求工程结构可维护**

> 代码结构按 Flask 应用工厂来组织，认证、问卷管理、公开填写分开，路由里不要堆业务逻辑。答案校验、跳转判断和统计分别拆到服务层，页面先用服务端渲染。配置从环境变量读，给 `.env.example`，再留一个健康检查接口，方便确认数据库是否真的连上。

**AI 响应**

- 生成应用工厂、三个 Blueprint 和三个 service 模块，路由只负责参数解析、调用服务和组织响应。
- 增加配置读取、`.env.example`、依赖清单和 `/health`。

**人工验收**

MongoDB 8.0 中集合与索引创建成功；应用启动后 `/health` 返回 200，数据库状态为 connected。

#### 3.1.3 账号、问卷、题目与跳转（P04—P05）

**第 1 轮：用户下达账号与权限命令**

> 先做注册、登录、退出。用户名限制 3 到 30 位中文、字母、数字或下划线，统一转小写后不能重复；密码至少 6 位，只能存哈希，不能存明文。登录后用会话保持状态，没登录不能建问卷也不能答题。问卷管理必须校验创建者，别人直接改 URL 不能看到我的问卷，也不要返回 403 告诉对方“这个问卷存在”。

**AI 响应**

- 使用 Werkzeug 的 scrypt 哈希保存密码，建立注册、登录、退出和登录保护。
- 所有管理接口校验 `owner_id`；非创建者统一返回 404，避免暴露资源是否存在。

**第 2 轮：用户追加跳转安全要求**

> 登录后的 `next` 参数也要检查，只允许站内路径，`//`、反斜杠、控制字符和外部地址都不能跳，异常时统一回“我的问卷”。这种细节不要等测试发现了才补。

**AI 响应**

- 增加站内跳转校验，拒绝协议相对地址、反斜杠和控制字符，异常目标回退到 `/dashboard`。

**第 3 轮：用户下达问卷、题目和跳转需求**

> 问卷要有草稿、发布、关闭三种状态，支持标题、说明、截止时间、匿名和是否允许重复填写。发布条件至少是一道题加有效截止时间，发布后生成公开链接。题型按四种控件做：单选、多选、文本、数字，必答、多选数量、文本长度、数字范围和整数都要在服务端校验。跳转规则要按选项或数值条件匹配，命中第一条就生效，没命中默认下一题；目标只能往后跳或结束问卷，不能形成死循环。选项用 A、B、C 这样的编号关联，删除题目时把指向它的规则一起清掉。

**AI 响应**

- 实现问卷状态机和公开编号生成，发布后锁定题目与跳转结构。
- 实现四类题型、服务端校验和 `rules` 服务；跳转目标只允许后续题目或 `END`，删除题目时清理相关规则。

**第 4 轮：用户补充截止时间行为**

> 截止时间不要依赖定时任务，用户打开管理页、公开页或答题页时检查一次，过期就把已发布问卷原子地改成关闭，之后不能再创建答卷。

**AI 响应**

- 在读取问卷的入口统一检查截止时间，使用条件更新把 `published` 改为 `closed`。

**人工验收**

发布后锁定、跳转不回退、删除题目清理规则、截止自动关闭均有测试覆盖。

#### 3.1.4 逐题答卷与重复提交控制（P06）

**第 1 轮：用户下达填写流程命令**

> 填写部分按公开链接进入，但必须先登录。先显示问卷说明，再一题一页地填，提交当前题时由服务端校验并计算下一题。每答完一题就保存，刷新或中途退出不能丢前面的答案；命中结束规则或答完最后一题后，答卷状态改成已提交。匿名问卷不能记录账号，允许重复填写的问卷要能区分多次答卷，不允许重复的只能提交一次。多人同时填写时，各自的答案不能串。

**AI 响应**

- 每次填写创建独立 response 文档，保存访问令牌、当前题、答案列表和提交状态。
- 每题提交时调用校验与跳转服务，答案立即写入 MongoDB；完成后记录提交时间。
- 同一账号的多次答卷通过 `respondent_key` 区分。

**第 2 轮：用户追问令牌与并行草稿**

> 访问令牌要随机生成，数据库里不要留可以直接拿来冒充答卷的明文。匿名模式不存用户 ID，但去重键要不可逆。还有，禁止重复填写时，如果我只检查“已提交”的答卷，用户开两个浏览器各建一份草稿就能绕过去；同一会话可以继续原来的草稿，其他会话不能再建第二份。

**AI 响应**

- 令牌只保存哈希，访问时比对哈希值。
- 匿名答卷使用 HMAC 去重键；开始填写前同时检查已提交答卷和未完成草稿。
- 增加部分唯一索引，防止并发请求在数据库层创建重复答卷。

**第 3 轮：用户补充关闭场景**

> 填写过程中问卷被关闭或到期，不能继续写；下一页要给出明确提示，不要出现 500 或继续提交成功。

**AI 响应**

- 在开始答卷和每次提交前检查问卷状态，关闭或到期时停止写入并显示关闭页面。

**人工验收**

逐题保存、刷新恢复、匿名、重复提交、并行草稿和关闭问卷均有集成测试。

#### 3.1.5 统计口径与页面（P07）

**第 1 轮：用户下达统计任务**

> 统计只算已经提交的答卷，填写中的草稿不能进结果。整卷页面要有总提交数、每道题的回答人数；单选和多选显示每个选项的次数和百分比，文本题列出回答内容，数字题给出全部值、平均值、最小值和最大值。还要能切到单题统计，并提供一个 JSON 接口，方便程序读取。

**AI 响应**

- 使用 MongoDB aggregation 的 `unwind`、`group` 完成整卷和单题统计。
- 生成统计页面和 `/api/surveys/<id>/stats` 接口，统计口径限定 `status=submitted`。

**第 2 轮：用户补充隐私与展示要求**

> 统计页面和 JSON 都不能出现答卷令牌、去重键、填写者账号这些内部字段，匿名问卷尤其不能反推出是谁填的。百分比的分母要说清楚，是回答该题的人数，不是总提交数。模板里别把字典字段名和方法名撞在一起。

**AI 响应**

- 统计结果只保留题号、题型、计数、比例和答案值，不返回身份字段。
- 百分比按该题实际回答人数计算。
- 发现 `values` 字段与 Jinja 字典方法冲突后，将字段改名为 `answer_values`。

**人工验收**

统计计数、百分比、数字均值、草稿排除和隐私字段检查均通过。

#### 3.1.6 自动化测试与实际运行（P08—P09）

**第 1 轮：用户下达测试命令**

> 给系统补 pytest，不要只测注册成功这种顺利路径。至少覆盖：账号隔离、创建问卷、添加题目、非法选项、必答、多选数量、文本长度、数字范围、跳转条件、默认下一题、结束问卷、逐题保存、提交、统计和重复提交。测试要用独立数据库，不能把开发数据清掉，也不要依赖执行顺序之外的隐藏状态。

**AI 响应**

- 建立测试夹具和隔离数据库，编写单元测试与集成测试。
- 初版 11 项测试通过，但发现测试在发布问卷后才添加跳转规则，与“发布后锁定”冲突。

**第 2 轮：用户要求按业务规则修正测试**

> 这个失败不要靠放宽业务规则解决。发布后锁定是明确需求，应该改测试顺序：先加题、配跳转，再发布和填写。测试应该验证真实规则，不是让规则迁就测试。

**AI 响应**

- 调整测试顺序，保留发布后锁定逻辑，初版测试恢复通过。

**第 3 轮：用户要求实际运行验证**

> 我们先测试一下是否能正常工作。不要只跑 pytest，实际把 MongoDB 和 Flask 起起来，访问 `/health`，然后走一遍真实流程：注册登录、建问卷、加题、配跳转、发布、打开公开链接、逐题作答、提交、看统计。中间发现问题就直接修，修完再走一遍，不要停在“应该可以”。

**AI 响应**

- 启动隔离 MongoDB 和 Flask，完成健康检查与真实 HTTP 流程。
- 登录、公开链接、逐题作答、跳转、提交和统计接口均通过。

**人工验收**

`/health` 返回 200 且 `database=connected`；业务链路实际跑通，不只依赖单元测试。

#### 3.1.7 隐私专项与补充测试（P10—P11）

**第 1 轮：用户提出隐私验证要求**

> 不是有需要我验证是否会暴露用户信息的测试吗，还是说我不需要再进行测试了？我担心三件事：匿名答卷还能不能在统计页或 JSON 里看到账号；答卷令牌会不会被别人猜到来接管答卷；另一个账号能不能通过改 URL 看到我的问卷或统计。你先检查代码和接口，再告诉我结论。

**AI 响应**

- 检查匿名答卷字段、访问令牌校验、统计接口返回字段、管理页权限和跨账号访问。
- 未发现匿名身份或令牌泄露；跨账号访问返回 404。

**第 2 轮：用户要求固化为测试**

> 不要只做一次手工检查，把这几项写成 `tests/test_privacy.py`，以后改代码也能回归。测试要明确断言：匿名答卷没有用户 ID，统计结果没有令牌和去重键，其他账号访问不到。

**AI 响应**

- 新增 2 项隐私测试并纳入测试套件。

**第 3 轮：用户要求继续补边界测试**

> 还有其他需要测试的吗，有的话直接测试并修改，不用先问我。重点看重复提交、并行草稿、登录跳转、`NaN` 和 `Infinity`、草稿关闭、截止时间自动关闭、匿名开关、删除题目后的跳转清理。发现问题直接改代码，改完跑全量回归，最后告诉我改了什么、测试总数是多少。

**AI 响应**

- 新增安全、边界和隐私测试，修复以下问题：

**P05 问卷、题目与条件跳转**

> 实现问卷草稿、发布、关闭三种状态，支持标题、说明、截止时间、匿名和是否允许重复填写。发布条件至少是一道题和有效截止时间，发布后生成随机公开编号和 `/survey/<public_id>` 链接。题型使用单选、多选、文本、数字四种控件，必答、多选最少/最多数量、文本长度、数字范围与整数校验全部在服务端执行。跳转规则按题目保存，支持按选项、文本或数字条件匹配，命中第一条生效，未命中默认下一题；目标只能是后续题目或结束问卷，禁止回跳形成死循环。选项使用 A、B、C 编号关联，删除题目时清理指向它的规则。发布后锁定题目和跳转结构；截止时间不依赖定时任务，读取问卷时检查并原子关闭。

**P06 逐题填写与答卷保存**

> 实现公开链接填写流程：进入前必须登录，先显示问卷说明，再一题一页作答。提交当前题时由服务端校验并计算下一题，每道有效答案立即写入 MongoDB，刷新或中途退出不能丢失已答内容。命中结束规则或答完最后一题后，答卷状态改为已提交并记录时间。匿名问卷不保存用户 ID；允许重复填写时用去重键区分多次答卷，不允许重复时同一会话可以继续原草稿，其他会话不能新建第二份，并用部分唯一索引防止并发绕过。访问令牌随机生成且只保存哈希，问卷关闭或到期后停止接收答案。

**P07 统计页面与 JSON 接口**

## 7. 最终实现中的设计选择

- 业务数据拆分为 `users`、`surveys`、`questions`、`responses` 四个集合，避免单集合存储所有内容。
- 答卷答案内嵌在 response 中，题目和跳转规则保存在 question 中。
- 问卷发布后锁定题目结构，保证已有答卷与题目引用一致。
- 跳转规则由 MongoDB 数据驱动，不在程序中写死具体问卷逻辑。
- 服务端完成答案校验、权限检查和下一题计算。
- 匿名答卷不保存用户身份，使用不可逆 `respondent_key` 执行重复提交限制。
- 禁止重复填写的问卷使用部分唯一索引，在数据库层防止并发创建重复答卷。
- 统计只计算已提交答卷，填写中的草稿不进入结果。
- 非创建者访问问卷返回 404，避免暴露资源是否存在。
